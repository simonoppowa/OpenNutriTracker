### ARB format in Weblate
- "ARB translations are monolingual"; typical config = filemask `lib/l10n/intl_*.arb`, base `lib/l10n/intl_en.arb`, template empty; capability table: Supports flags No, read-only No, removing obsolete No, check flags "ICU MessageFormat". https://docs.weblate.org/en/latest/formats/arb.html. "Keep this field empty for most of the monoligual formats." https://docs.weblate.org/en/latest/admin/projects.html#template-for-new-translations
- translate-toolkit `jsonl10n.py`: `@@` keys become one header unit and are written back; other `@key` objects are attached whole to the unit's metadata and written adjacent to the key, only when non-empty (PR https://github.com/translate/translate/pull/6014, release 3.18.1); the whole file is re-serialised with `json.dumps` on every save; toolkit's own ARB indent default is 2 (commit 28f6e3b553).
- Weblate `ARBFormat(JSONFormat)`: `unit_class = PlaceholdersJSONUnit`, `check_flags = ("icu-message-format",)`, `empty_file_template = "{}\n"` (weblate/formats/ttkit.py). On first translation of a key absent from a locale file, `clone_template` shallow-copies the template unit, so its `@key` dict (placeholders) is written into the locale file; only `notes` are stripped. Export: fr/hu/ru 50/50, es 24/24, sv 1/1 `@key` blocks byte-identical to the template. Template metadata is never re-synced later (https://github.com/WeblateOrg/weblate/issues/11133).
- "It does not however perform any automatic cleanup of stale strings". https://docs.weblate.org/en/latest/devel/integration.html#updating-target-files
- File format parameters (component level; the old "Customize JSON output" add-on was "Removed in version 5.13"): `json_indent` (IntegerField, default 4, `min_value` 0), `json_indent_style`, `json_sort_keys` (default `none`), `json_use_compact_separators` (default False); `JSONOutputIndentStyle.setup_store` always applies `json_indent`, so 4 overrides the toolkit's 2. https://docs.weblate.org/en/latest/formats.html#file-format-params, https://docs.weblate.org/en/latest/admin/addons.html, weblate/trans/file_format_params.py. Export: Weblate-written es/fr/hu/ru/sv are 4-space; untouched cs/de/en/it/pl/sk/tr/uk/zh are 2-space; key order in Weblate files is translation order.
- Language code style `""` = "Default based on the file format"; ARB inherits `language_format = "posix"` (base.py) → `intl_pt_BR.arb`, `intl_zh_Hans.arb`; the setting "only influences how new files are created". https://docs.weblate.org/en/latest/admin/projects.html#language-code-style. Parsing normalises case, underscores/dashes, default country codes. https://docs.weblate.org/en/latest/admin/languages.html#parsing-language-codes
- `new_lang` options: `contact`, `url`, `add` (model default), `existing` ("Create existing project languages; contact maintainers for new languages"), `none`; "The project admins can add new translations even if it is disabled here". https://docs.weblate.org/en/latest/admin/projects.html#adding-new-translation. "If you add a language file in connected remote repository, respective translation is added to the component when Weblate updates local repository." https://docs.weblate.org/en/latest/devel/translations.html#adding-translation
- Placeholders flag derived from ARB metadata takes the WebExtension branch → `case-insensitive, placeholders:$SOURCENAME$` (live on https://hosted.weblate.org/api/translations/opennutritracker/app/sv/units/?q=key%3AadditionalInfoLabelSource); since `$…$` never occurs in the source the check is inert. The ICU MessageFormat check is auto-enabled for ARB; sub-checks relax via `icu-flags:-types/-extra/-missing/…`. https://docs.weblate.org/en/latest/user/checks.html#check-icu-message-format. ARB `type` hints are not read (https://github.com/WeblateOrg/weblate/issues/17269, open; nijel in #16619: "Weblate doesn't see the ARB metadata").
- Weblate writes translated **and** needs-editing keys under `commit_policy=0`; untranslated keys are omitted (export: es 227 keys = 226 translated + 1 needs-editing; sv 10; `intl_pt_BR.arb` = `{}`; `c486673:lib/l10n/intl_ru.arb` = `{}`). No `""` values anywhere in this export; musicpod's Weblate-written ARBs carry `""` for 644/771 untranslated units.

## 2. Corrections (verifier-refuted or narrowed)
- `github.com/weblate.keys` lists 8 keys (7 RSA + 1 Ed25519 `…IFOT4xbZ6FFz…`), not just the RSA key; Hosted's published Ed25519 key `…INl+lWmT…` is absent from it.
- "Translations update from Hosted Weblate" is not the 2026.9.1 default (the tag ships `chore(l10n): update translations`); it is a per-component/project override or an older deployed template.
- App permission values come from `GET https://api.github.com/apps/hosted-weblate`, not the HTML page at github.com/apps/hosted-weblate.

## 4. Implications for the decisions (constraints only)

### (a) Which branch Weblate tracks
- A component tracks one branch; the webhook only updates components whose `branch` equals the pushed ref, so a `main` component ignores pushes to `develop` and vice versa (hooks.py L1234-1243).
- A Weblate PR's base is always the component's Repository branch (git.py `create_pull_request`); `main` needs a PR with 0 approvals (auto-merge can satisfy it), `develop` needs 1 human approval.
- Repo flow (context): features → `develop`, `release/*` → `main`, hotfixes as PR pairs. Nothing in Weblate propagates a commit from one branch to the other.
- Rebase style breaks once earlier Weblate commits are squash-merged upstream (continuous.html, FAQ); regular merge commits are required for recovery.
- Weblate's working copy is a shallow clone rooted at `294debe6` on the `main` lineage; the six new ARBs exist only there and rebase cleanly onto current `main`.
- Precedent: Finamp tracks its dev branch `redesign`; the other seven track `main`/`master`.

### (b) Write-back mode (direct push vs PR)
- Today `push=""` → nothing is ever written back, whatever `push_on_commit` says.
- Direct push to `main`/`develop`/`release/**` by a `weblate` write collaborator is rejected: PR required, no bypass list on a personal repo, ruleset forbids non-fast-forward. A separate push branch outside the ruleset can take forced pushes (needed with rebase + `git_force_push`).
- Inviting `weblate` on a personal repo necessarily grants write to the whole repo.
- `vcs=github` fork mode needs no push URL and no invite is documented (open question 1); Push-branch mode skips the fork, force-pushes the upstream branch, needs write; the open PR is updated in place and a fresh PR follows each merge; the fork's Actions are disabled.
- GitHub App backend needs the project in a workspace, drops push URLs, needs no invite/webhook; docs prefer it.
- `merge_request_automerge` / `merge_request_merge_method` exist on Hosted (2026.9); auto-merge waits for required checks.
- PR title comes from `pull_message`; the upstream default is `chore(l10n): update translations`, observed Hosted titles differ.
- Timing: lazy commits + 24 h age + hourly sweep → first write-back roughly 24–25 h after the first edit unless another trigger fires; push on commit is on.
- Commits are GPG-signed by Hosted's key; rebase re-signs and rewrites SHAs, authors preserved.
- A failed push/merge/fetch raises a locking alert; `auto_lock_error` is true, so translators are locked out until it clears.

### (c) All locales in a dev PR vs English-only; `check_l10n`
- gen-l10n never fails on a partial ARB (exit 0, English compiled in, listed in `l10n_untranslated.json`); `check_l10n` is the only thing that fails, and it has no per-locale allowance.
- Weblate omits untranslated keys (this repo's export), so any language not at 100 % in Weblate makes `check_l10n` fail once merged; fr/hu/ru are 900 of 1044 keys, es 227, sv 10, pt_BR 0.
- Weblate can also emit `""` (musicpod); gen-l10n treats `""` as translated and renders a blank; mechanism unknown.
- Non-default `commit_policy` removes keys from ARBs; flag add-ons (`source_edit` etc.) store state in Weblate only and are safe for files while `commit_policy=0`.
- Only Prefill (every language, no config), Pseudolocale (one target), or Automatic translation in translate/fuzzy/approved mode write strings into files; suggest mode writes nothing.
- Language filter regex excludes a language from scanning and file creation but does not touch files already in the repo.
- On 3.44.6 a `pt` + `pt_BR` pair cannot pass `check_l10n` unless `pt_BR` duplicates every key (#176020).
- None of eight surveyed Flutter+Weblate projects gates on completeness; FluffyChat greps for `": ""`.

### (d) Onboarding a new language (beyond the ARB)
- Files touched per locale: `intl_<code>.arb`, `Info.plist` `CFBundleLocalizations` (drift test), `locales_config.xml` (unguarded), `settings_screen.dart` map (unguarded), CONTRIBUTING (unguarded).
- A region/script locale requires its base file (`intl_pt.arb` for `intl_pt_BR.arb`) or gen-l10n exits 1; the export already contains `intl_pt_BR.arb` = `{}` with no `intl_pt.arb`.
- A language code outside gen-l10n's ISO-639 set needs `@@locale`; Weblate writes none (`nap` fails, `fil` passes).
- Weblate names new files POSIX-style (`intl_pt_BR.arb`); a BCP-style file would parse to the same locale and collide.
- `new_lang=add` lets any registered user create a `{}` file; `contact`/`existing`/`none` route the request to maintainers, who can still add languages; a language file committed upstream is adopted on the next update; disabling does not undo discovery of committed files.
- "Add missing languages" would add glossary-only languages to `app` as `{}` files.
- A partial locale is in `supportedLocales` and selectable by language code, regardless of completeness.
- `zh` + `zh_Hans` is a Weblate single-language collision (#5427) while gen-l10n demands both files (open).
- Precedents: wger's `check_locales.dart`, FluffyChat's generated `locale_config` + diff check, Every Door's CI `echo '{}' > app_zh.arb`.

### (e) ARB formatting / indent and @-metadata round-trip
- Weblate re-dumps a whole file with `json.dumps` on every save; `json_indent` (default 4) always overrides the toolkit's 2; 2 is a legal value (`min_value` 0); the component currently has 4. Changing it re-indents each already-4-space file once on its next save.
- `json_sort_keys=none` keeps insertion order (sorting would move every `@key` ahead of plain keys); `json_use_compact_separators=false` matches the repo's `", "`/`": "`; the serializer appends a trailing newline; Weblate-created files are in translation order, not template order.
- `@key` blocks are parsed whole, written adjacent, only when non-empty (3.18.1+); the template's `@key` is copied into a locale file on first translation and never re-synced (#11133). gen-l10n merges per-locale `@key` by name, so identical copies are no-ops; a stale copy with a renamed placeholder would override by name.
- The template's orphan `"@PHYSICAL_ACTIVITIES": {}` is skipped by Weblate and would be lost if Weblate ever rewrote `intl_en.arb`.
- `@@locale`: never added, existing ones preserved; gen-l10n treats it as optional and errors only on mismatch.
- Stale keys stay in locale files unless the Cleanup add-on runs; gen-l10n ignores extras.
- Placeholder flag from metadata is inert (`$NAME$` form); ICU MessageFormat check does the work and cannot read ARB `type` hints; ARB stores no flags or state.

### (f) Which add-ons to enable
- Live `addons=[]`; whether Hosted hides any add-on for Libre projects is unverified (page 403).
- Squash: post-commit, loses authorship unless "Per author"; docs pair it with webhook updates to avoid conflicts.
- Cleanup translation files: removes stale keys on post-update/pre-commit; Remove blank strings: drops `""` values.
- `source_edit`/`target_edit`/`same_edit`/`target_repo_update`: Weblate-only state; harmless to files only while `commit_policy=0`.
- Add missing languages: project/category scope; would generate `{}` ARBs from the glossary component.
- Pseudolocale: commits a full `intl_en_XA.arb`-style shipping locale (gen-l10n handling unverified).
- Prefill: fills every untranslated string with source as needs-edit; the only add-on that keeps every ARB complete without configuration; needs `commit_policy=0`.
- Automatic translation: default suggest mode writes nothing; translate/fuzzy/approved write; site-wide engine roster for Libre unknown.
- `enforced_checks: ["icu_message_format"]` marks failures Needs editing; under `commit_policy=0` the string is still written (gen-l10n rejects bad ICU at build), under `commit_policy=1` the key is omitted (`check_l10n` fails).
- Unchanged translation is always on; per-string `ignore-same`, glossary Untranslatable terms + `check-glossary`, or component `check_flags` silence it; enforcing it is discouraged.
- Propagation is irrelevant with one ARB component; docs advise off for monolingual.

### (g) Clearing "Repository outdated" and recovering the six languages
- The alert means `count_missing() > 25` (Weblate counts 1388 on its shallow graph); it clears on the daily task, a successful `do_update`/`update_branch`, or a successful push. No push URL, no webhook, and (inferred) fetch-only `AUTO_UPDATE` mean nothing clears it automatically.
- A full update runs only from: a GitHub webhook to `https://hosted.weblate.org/hooks/github/` on a push to the tracked branch (none exists today), a manual Update / Update with rebase (UI, REST `operation=pull`, wlc), or a push path.
- Update with rebase runs `git rebase --gpg-sign origin/main`; the 23 Weblate commits rebase cleanly (dry run on Weblate's own graph) because `intl_{es,fr,hu,pt_BR,ru,sv}.arb` do not exist upstream; a failure would raise `MergeFailure` and auto-lock the component.
- After the rebase Weblate re-parses against the current `intl_en.arb` (1036 strings as Weblate counts / 1044 non-`@` keys), so fr/hu/ru drop from 100 % without conflicts.
- Pending translations are DB rows and survive Update, Update with rebase and Reset and reapply; only Reset and discard drops them.
- The six ARBs are publicly cloneable from the export; nothing pushes them while `push=""`. Merged as-is they break gen-l10n (`pt_BR` without `pt`), then `check_l10n` on all six; they are 4-space, translation-ordered, without `@@locale`, with template-identical `@key` blocks.
- Rebasing rewrites the 23 SHAs and re-signs them; a squash merge of Weblate commits upstream makes later rebases fail (docs/FAQ).
- "Repository has changes" fires at > 25 outgoing commits (23 today).
- `new_lang=add` remains live, so further `{}` files can appear at any time.
