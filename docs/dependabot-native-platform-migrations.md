# Dependabot native-platform and lockfile classification

Research for [Classify native platform and lockfile migrations](https://github.com/simonoppowa/OpenNutriTracker/issues/741), against `develop` at `3f5f1a45` and the exact versions proposed by the open Dependabot pull requests.

## Decision

The Flutter plugin upgrades can go into one rollup, but two native changes must be part of that same pull request before it is considered mergeable:

1. Raise the app's Android Gradle Plugin from 8.11.1 to **at least 8.12.1** for `share_plus` 12.0.2. Keep the proposed version narrowly scoped to 8.12.1 unless the rollup separately decides to take a newer version.
2. Regenerate **one combined `ios/Podfile.lock`** after all Dart constraints have been applied. It must update Sentry Cocoa from 8.58.1 to 8.58.4, remove Mantle through the image-compress change, and record the new local-pod checksums, including `flutter_timezone`.

No iOS deployment-target bump, CocoaPods upgrade, Android SDK bump, application-manifest addition, Apple entitlement, or checked-in generated registrant is required. The Dart API migrations for `flutter_timezone` and `flutter_local_notifications` remain mandatory, but are not native-platform migrations.

| Proposed upgrade | Native classification | Required in the rollup |
|---|---|---|
| [`sentry_flutter` 9.26.0](https://github.com/simonoppowa/OpenNutriTracker/pull/609) | iOS lock migration | Refresh `Sentry/HybridSDK` to 8.58.4 in the combined `Podfile.lock`. |
| [`share_plus` 12.0.2](https://github.com/simonoppowa/OpenNutriTracker/pull/564) | Android toolchain migration | Set AGP to >=8.12.1; existing Gradle, Kotlin, Java, SDK, manifest, and iOS target are sufficient. |
| [`flutter_image_compress` 2.5.1](https://github.com/simonoppowa/OpenNutriTracker/pull/611) | Lockfile-only native change | Preserve the PR's removal of Mantle by regenerating, not hand-merging, the combined lock. |

| [`flutter_local_notifications` 20.1.0](https://github.com/simonoppowa/OpenNutriTracker/pull/573) | Dart migration; native host already ready | No manifest, entitlement, deployment-target, or Gradle migration beyond the rollup's `share_plus` AGP change. |

The native-clean classifications follow the published package shapes as well as the PR diffs. `image_picker` 1.2.3 changes the app-facing Dart package and its SDK floor without changing resolved `image_picker_android` or `image_picker_ios` ([release source](https://github.com/flutter/packages/blob/image_picker-v1.2.3/packages/image_picker/image_picker/CHANGELOG.md), [PR diff](https://github.com/simonoppowa/OpenNutriTracker/pull/608/files)). `supabase_flutter` declares platforms but no Flutter plugin implementation; 2.16.0 adds a Dart `passkeys_platform_interface` dependency, not a native authenticator ([published pubspec](https://github.com/supabase/supabase-flutter/blob/supabase_flutter-v2.16.0/packages/supabase_flutter/pubspec.yaml), [release source](https://github.com/supabase/supabase-flutter/blob/supabase_flutter-v2.16.0/packages/supabase_flutter/CHANGELOG.md)). `path_provider_platform_interface` is likewise an interface package and is only a development dependency here ([PR diff](https://github.com/simonoppowa/OpenNutriTracker/pull/610/files)).

## Android: only `share_plus` forces a host migration

`share_plus` 12.0.0 introduced an explicit Android floor of AGP 8.12.1, Gradle 8.13, Kotlin 2.2.0, and Java 17; 12.0.2 retains those requirements ([published changelog](https://github.com/fluttercommunity/plus_plugins/blob/share_plus-v12.0.2/packages/share_plus/share_plus/CHANGELOG.md), [published README](https://github.com/fluttercommunity/plus_plugins/blob/share_plus-v12.0.2/packages/share_plus/share_plus/README.md), [Android source](https://github.com/fluttercommunity/plus_plugins/blob/share_plus-v12.0.2/packages/share_plus/share_plus/android/build.gradle)). The app currently has AGP 8.11.1, Gradle 8.14, Kotlin 2.2.20, Java 17, compile/target SDK 36, and Flutter's current minimum SDK ([settings](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/android/settings.gradle), [wrapper](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/android/gradle/wrapper/gradle-wrapper.properties), [app Gradle](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/android/app/build.gradle)). Android's compatibility table says AGP 8.12 requires Gradle 8.13, so the existing 8.14 wrapper is already adequate ([Android Developers](https://developer.android.com/build/releases/about-agp#updating-gradle)).

The other native plugins fit inside those existing floors:

- `flutter_timezone` 5.1.0 requires Java 17, compile SDK 35, minimum SDK 21, and iOS 11 ([changelog](https://github.com/tjarvstrand/flutter_timezone/blob/v5.1.0/CHANGELOG.md), [Android source](https://github.com/tjarvstrand/flutter_timezone/blob/v5.1.0/android/build.gradle), [podspec](https://github.com/tjarvstrand/flutter_timezone/blob/v5.1.0/ios/flutter_timezone.podspec)).
- `flutter_local_notifications` 20.1.0 requires Java 17, desugaring, compile SDK 35, and minimum SDK 21 ([changelog](https://github.com/MaikuB/flutter_local_notifications/blob/flutter_local_notifications-v20.1.0/flutter_local_notifications/CHANGELOG.md), [Android source](https://github.com/MaikuB/flutter_local_notifications/blob/flutter_local_notifications-v20.1.0/flutter_local_notifications/android/build.gradle)). The app already enables core-library desugaring 2.1.4 and uses Java 17.
- `flutter_image_compress_common` 1.1.1 requires Java 17, compile SDK 34, and minimum SDK 21 ([published Android source](https://github.com/fluttercandies/flutter_image_compress/blob/flutter_image_compress-v2.5.1/packages/flutter_image_compress_common/android/build.gradle)).
- `sentry_flutter` 9.26.0 declares compile/target SDK 36 and minimum SDK 21 ([published Android source](https://github.com/getsentry/sentry-dart/blob/9.26.0/packages/flutter/android/build.gradle)).

The application's notification manifest already declares notification permission, reboot permission, and both scheduling receivers. It uses inexact scheduling, so neither exact-alarm permission is needed. The plugin contributes `VIBRATE` through manifest merging. `share_plus` contributes its non-exported file provider and result receiver from the plugin manifest. No manual copies belong in the app manifest ([app manifest](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/android/app/src/main/AndroidManifest.xml), [notification service](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/lib/core/utils/notification_service.dart), [notification plugin setup](https://github.com/MaikuB/flutter_local_notifications/blob/flutter_local_notifications-v20.1.0/flutter_local_notifications/README.md#androidmanifestxml-setup), [`share_plus` manifest](https://github.com/fluttercommunity/plus_plugins/blob/share_plus-v12.0.2/packages/share_plus/share_plus/android/src/main/AndroidManifest.xml)).

## iOS: regenerate the lock once, do not combine three lock diffs by hand

The app target and Podfile are already iOS 15.5. All proposed plugins are lower: Sentry 12, `share_plus` 12, notification/timezone 11, and image compression 9 ([Podfile](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/ios/Podfile), [Sentry podspec](https://github.com/getsentry/sentry-dart/blob/9.26.0/packages/flutter/ios/sentry_flutter.podspec), [`share_plus` podspec](https://github.com/fluttercommunity/plus_plugins/blob/share_plus-v12.0.2/packages/share_plus/share_plus/ios/share_plus.podspec), [notification podspec](https://github.com/MaikuB/flutter_local_notifications/blob/flutter_local_notifications-v20.1.0/flutter_local_notifications/ios/flutter_local_notifications.podspec), [timezone podspec](https://github.com/tjarvstrand/flutter_timezone/blob/v5.1.0/ios/flutter_timezone.podspec), [compression podspec](https://github.com/fluttercandies/flutter_image_compress/blob/flutter_image_compress-v2.5.1/packages/flutter_image_compress_common/ios/flutter_image_compress_common.podspec)). No deployment-target change is needed.

The Sentry failures are deterministic lock drift, not an Xcode, deployment-target, or Sentry API failure. PR 609 leaves `ios/Podfile.lock` at `Sentry/HybridSDK` 8.58.1, while Sentry Flutter 9.26.0 pins 8.58.4. The [failed iOS build](https://github.com/simonoppowa/OpenNutriTracker/actions/runs/30769373598/job/91553690452) reports that exact conflict. The then-current fallback found the correct root pod but used a Bash-4 associative array on macOS's Bash 3.2, so it stopped before `pod update Sentry`. `develop` has since replaced that construct and added a compatibility guard ([current fallback](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/.github/scripts/pod_install_with_targeted_fallback.sh), [fix commit](https://github.com/simonoppowa/OpenNutriTracker/commit/86672b216)).

CocoaPods documents that `pod install` preserves versions already recorded in `Podfile.lock`, while `pod update PODNAME` intentionally re-resolves only that named pod; a bare `pod update` would unnecessarily re-resolve all pods ([CocoaPods guide](https://guides.cocoapods.org/using/pod-install-vs-update.html)). The rollup should therefore use the repository's targeted fallback or explicitly update `Sentry`, then commit the resulting single lock. The regeneration also needs to reproduce PR 611's removal of Mantle and PR 569's `flutter_timezone` checksum. Individual `pubspec.lock` and `Podfile.lock` hunks were resolved against different historical bases and must not be stacked manually ([compression diff](https://github.com/simonoppowa/OpenNutriTracker/pull/611/files), [timezone diff](https://github.com/simonoppowa/OpenNutriTracker/pull/569/files)).

`flutter_image_compress` 2.5.x adds Swift Package Manager support and removes Mantle from its CocoaPods path, but SPM support is optional ([changelog](https://github.com/fluttercandies/flutter_image_compress/blob/flutter_image_compress-v2.5.1/CHANGELOG.md)). This repository deliberately disables SPM in CI and uses CocoaPods because unsigned CI builds cannot currently satisfy SPM product-signing requirements ([workflow](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/.github/workflows/default_workflow.yml)). Do not add `Package.resolved` or convert the app as part of this rollup.

The iOS Fastlane proposal keeps CocoaPods at 1.17.0 and xcodeproj at 1.28.1, so no Ruby/CocoaPods migration is hidden inside that lockfile update ([Fastlane PR](https://github.com/simonoppowa/OpenNutriTracker/pull/693/files), [Gemfile](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/ios/Gemfile)).

No new entitlement is required. `flutter_local_notifications` 20.1 adds opt-in CarPlay authorization, defaulting off; the app does not request it. Existing camera and photo-library usage descriptions already cover `image_picker`, and the 1.2.3 PR does not update either endorsed native implementation ([notification release](https://github.com/MaikuB/flutter_local_notifications/blob/flutter_local_notifications-v20.1.0/flutter_local_notifications/CHANGELOG.md), [CarPlay default](https://github.com/MaikuB/flutter_local_notifications/blob/flutter_local_notifications-v20.1.0/flutter_local_notifications/lib/src/platform_specifics/darwin/initialization_settings.dart), [`image_picker` release](https://github.com/flutter/packages/blob/image_picker-v1.2.3/packages/image_picker/image_picker/CHANGELOG.md), [Info.plist](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/ios/Runner/Info.plist)).

## Why two PR heads report no checks

The current heads of PR 611 and PR 569 are CI-created `chore(ios): refresh Podfile.lock and project.pbxproj via CI` commits, not the original Dependabot commits. Their original heads did run CI:

- PR 611's original head passed Linux, Android/iOS builds, and both integration suites; only the lock guard failed. The iOS build refreshed and auto-committed the lock, leaving the new head without attached checks ([original checks](https://github.com/simonoppowa/OpenNutriTracker/commit/490f710a3224f485e1271a6a87e7da55cfee2b76/checks), [current commit list](https://github.com/simonoppowa/OpenNutriTracker/pull/611/commits)).
- PR 569's original head failed analysis and both platform builds because `getLocalTimezone()` now returns `TimezoneInfo`, not `String`; this was a Dart compile failure, not a native-platform failure. Its later CI lock commit likewise became a head with no attached checks ([original checks](https://github.com/simonoppowa/OpenNutriTracker/commit/b816c7db69cc1e9e8c11b86ed1314856f4c441e9/checks), [current commit list](https://github.com/simonoppowa/OpenNutriTracker/pull/569/commits), [5.0 breaking change](https://github.com/tjarvstrand/flutter_timezone/blob/v5.1.0/CHANGELOG.md#500)).

GitHub generally suppresses recursive workflow events created with `GITHUB_TOKEN`; its documented pull-request exception produces approval-required runs rather than guaranteeing a normal automatic rerun ([GitHub token documentation](https://docs.github.com/en/actions/concepts/security/github_token#when-github_token-triggers-workflow-runs)). Therefore “no checks reported” on these two current SHAs is not positive evidence. The rollup must run a fresh complete workflow on its final combined head.

## Generated registrants

The iOS `Runner/GeneratedPluginRegistrant.*` and Android `GeneratedPluginRegistrant.java` are intentionally ignored, so no generated registrant belongs in the rollup commit ([iOS ignore](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/ios/.gitignore), [Android ignore](https://github.com/simonoppowa/OpenNutriTracker/blob/3f5f1a45/android/.gitignore)). `flutter pub get` and a clean native build must regenerate them locally after the final combined `pubspec.lock`. Flutter's package documentation explicitly requires fetching and rebuilding when a dependency contains platform code ([Flutter documentation](https://docs.flutter.dev/packages-and-plugins/using-packages#adding-a-package-dependency-to-an-app)).

Because several upgrades change plugin implementations without changing plugin names, source inspection of a generated registrant is weaker than a runtime smoke test. The final app-boot integration tests should prove registration by invoking timezone lookup and notification initialization; targeted tests should also exercise image compression, image picking, sharing, and Sentry initialization on their native platforms.

## Rollup sequence and targeted native verification

1. Apply every proposed `pubspec.yaml` constraint plus the `flutter_timezone` and `flutter_local_notifications` Dart migrations.
2. Raise AGP to 8.12.1. Leave Gradle 8.14, Kotlin 2.2.20, Java 17, compile/target SDK 36, and minimum SDK unchanged.
3. Run `flutter pub get` once and commit its single resolved `pubspec.lock`; do not concatenate Dependabot lock hunks.
4. With Flutter SPM disabled as in CI, run the repository's targeted pod-install fallback on macOS. Confirm `Sentry/HybridSDK` is 8.58.4, Mantle is absent, the timezone/compression checksums are refreshed, and an immediate second `pod install` produces no diff. Commit `ios/Podfile.lock` and any legitimate CocoaPods `project.pbxproj` change.
5. Run the complete CI workflow on the final head, including the Podfile-lock guard, unsigned iOS build, Android build, and both integration suites.
6. Add native feature smokes proportional to the upgrades:
   - Android: inspect the merged full-flavor manifest for notification receivers, `share_plus` provider/receiver, and expected Sentry initialization behavior; test notification permission on API 33+, scheduling/reboot restoration, timezone lookup, file sharing, picker return, and JPEG compression.
   - iOS: build at the app's 15.5 deployment target, then test timezone lookup, notification permission/scheduling and foreground delegate behavior, photo picking, share sheet invocation, JPEG/WebP compression (including `keepExif`), and Sentry startup on a simulator or device.

Passing the existing native build and integration jobs is the minimum merge gate. PRs 608, 568, and 564 already have successful Android and iOS build/integration evidence on their isolated heads, but that evidence cannot substitute for the combined run because the rollup changes the shared Dart, Gradle, and CocoaPods resolution surfaces ([image-picker checks](https://github.com/simonoppowa/OpenNutriTracker/pull/608/checks), [Supabase checks](https://github.com/simonoppowa/OpenNutriTracker/pull/568/checks), [`share_plus` checks](https://github.com/simonoppowa/OpenNutriTracker/pull/564/checks)).
